# 非機能要件

## 概要

障害者雇用支援アセスメントシステムの非機能要件を定義します。
本システムは障害・診断情報という要配慮個人情報を取り扱うため、セキュリティおよび個人情報保護を最重要要件と位置づけます。

---

## 1. セキュリティ要件

### 1-1. 認証・認可

| 要件ID | 要件 | 詳細 |
|-------|------|------|
| SEC-01 | パスワードポリシー | 8文字以上、英大文字・英小文字・数字・記号を各1文字以上含む |
| SEC-02 | パスワードハッシュ化 | bcrypt または Argon2 を使用してハッシュ化して保存する |
| SEC-03 | セッション管理 | ログイン後はセッショントークン（JWT または Cookie）を発行し、一定時間（30分）操作がない場合は自動ログアウトする |
| SEC-04 | ロールベースアクセス制御（RBAC） | 組織管理者・担当者のロールに応じて操作可能な機能を制限する（詳細は `08_role-permission.md` 参照） |
| SEC-05 | テナント分離 | すべての API レスポンスはログインユーザーの `organization_id` でフィルタリングし、他組織のデータを返さない |
| SEC-06 | ブルートフォース対策 | ログイン失敗が5回連続した場合、15分間ロックアウトする |

---

### 1-2. 通信・データ保護

| 要件ID | 要件 | 詳細 |
|-------|------|------|
| SEC-07 | 通信の暗号化 | すべての通信は HTTPS（TLS 1.2 以上）で行う。HTTP アクセスは HTTPS にリダイレクトする |
| SEC-08 | 保存データの保護 | データベースの保存データは暗号化（AES-256）して保存する |
| SEC-09 | 機密フィールドの扱い | 障害種別・診断名・評価スコア等の要配慮個人情報はログに出力しない |
| SEC-10 | PDF セキュリティ | 出力する PDF にパスワード保護オプションを設ける（任意） |

---

### 1-3. 脆弱性対策

| 要件ID | 要件 | 詳細 |
|-------|------|------|
| SEC-11 | SQL インジェクション対策 | ORM のパラメータバインドを使用し、生 SQL での文字列結合を禁止する |
| SEC-12 | XSS 対策 | ユーザー入力値は HTML エスケープ処理を行う。CSP（Content Security Policy）ヘッダを設定する |
| SEC-13 | CSRF 対策 | 状態変更を伴うリクエストには CSRF トークンを検証する |
| SEC-14 | 依存パッケージ管理 | 既知の脆弱性を持つパッケージを定期的に検出・更新する（Dependabot 等の活用） |

---

## 2. 個人情報保護要件

本システムは個人情報保護法における「要配慮個人情報」（障害・疾病・診断情報）を取り扱うため、通常の個人情報より厳格な管理が求められます。

| 要件ID | 要件 | 詳細 |
|-------|------|------|
| PII-01 | 取得目的の限定 | 支援業務の目的に必要な情報のみを取得・保存する |
| PII-02 | アクセス範囲の限定 | 支援対象者の情報は、同一組織内の担当者および組織管理者のみがアクセス可能とする |
| PII-03 | データの最小化 | 支援に不要な個人情報は収集しない |
| PII-04 | 保存期間 | 利用組織の契約終了後、データを保存する期間は契約で定める。期間経過後はデータを削除する |
| PII-05 | データエクスポート | 利用組織がデータエクスポートを要求した場合、管理者が対応できる仕組みを用意する |
| PII-06 | データ削除対応 | 支援対象者の情報削除要求に対応できる仕組みを用意する（論理削除または物理削除） |
| PII-07 | 監査ログ | 要配慮個人情報へのアクセス・変更操作はログに記録し、一定期間保持する |

## 3. 可用性・性能要件

### 3-1. 可用性

| 要件ID | 要件 | 詳細 |
|-------|------|------|
| AVL-01 | 稼働率 | 99.5% 以上（月間メンテナンス時間を除く） |
| AVL-02 | 計画メンテナンス | 事前にユーザーへ通知した上で実施する。原則として業務時間外（平日22時〜翌6時）に行う |
| AVL-03 | バックアップ | データベースは日次でバックアップを取得し、7日間保持する |
| AVL-04 | 障害復旧目標（RTO） | 障害発生から4時間以内にサービスを復旧する |
| AVL-05 | 復旧ポイント目標（RPO） | 最大24時間前の状態まで復旧できること |

---

### 3-2. 性能

| 要件ID | 要件 | 詳細 |
|-------|------|------|
| PER-01 | 画面表示速度 | 通常操作時のページ表示は3秒以内（一覧・フォーム画面） |
| PER-02 | PDF 生成速度 | PDF 出力処理は10秒以内に完了する |
| PER-03 | 同時接続数 | 1組織あたり最大50ユーザーの同時接続を想定する |
| PER-04 | データ量 | 1組織あたり支援対象者1,000件・アセスメント10,000件を上限の目安とする |

---

## 4. 保守性・運用要件

| 要件ID | 要件 | 詳細 |
|-------|------|------|
| OPS-01 | ログ管理 | アプリケーションログ・アクセスログ・エラーログを分離して記録する。ログは30日間保持する |
| OPS-02 | エラー通知 | サーバーエラー（5xx）発生時は開発・運用担当者にアラートを通知する |
| OPS-03 | モニタリング | CPU・メモリ・ディスク・レスポンスタイムを常時監視する |
| OPS-04 | デプロイ | ダウンタイムなしでデプロイできる方式（Blue/Green または Rolling Update）を採用する |
| OPS-05 | ブラウザ対応 | Chrome・Edge・Safari の最新2バージョンを動作保証対象とする |
| OPS-06 | デバイス対応 | PC（1280px以上）でのデスクトップ利用を主要対象とする。スマートフォン対応は対象外 |

---

## 5. 法令・コンプライアンス要件

| 要件ID | 要件 | 関連法令 |
|-------|------|---------|
| COM-01 | 要配慮個人情報の適切な管理 | 個人情報保護法 第2条・第20条 |
| COM-02 | 安全管理措置の実施 | 個人情報保護法 第23条 |
| COM-03 | 第三者提供の禁止 | 支援対象者の情報を本人の同意なく第三者に提供しない（個人情報保護法 第27条） |
| COM-04 | 合理的配慮の記録 | 障害者差別解消法・障害者雇用促進法に基づく合理的配慮の記録を個別支援計画に残せること |
