# プロダクト要求定義書 - 注文管理システム（OrderHub）

## 概要
ECサイトの注文管理システム「OrderHub」を構築する。
本プロジェクトは、DDD（ドメイン駆動設計）およびレイヤードアーキテクチャの実践例として、チームメンバーがこれらの設計手法の意義と適用方法を学ぶことを目的とする。

## 背景と目的
- レイヤードアーキテクチャにおける各層の責務分離を具体的に示す
- ドメインモデルにビジネスロジックを集約するメリットを体感する
- 集約・値オブジェクト・ドメインイベント・リポジトリパターンなどDDDの主要パターンを実装で例示する

## 主要な機能一覧

### 1. 商品カタログ管理
- 商品の登録・更新・削除
- 商品カテゴリの管理
- 在庫数の管理

### 2. 注文管理
- 注文の作成（カートから注文への変換）
- 注文ステータスの遷移管理（確定 → 支払済 → 出荷準備中 → 出荷済 → 配達完了）
- 注文キャンセル（キャンセルポリシーに基づく制御）
- 注文明細の管理

### 3. 顧客管理
- 顧客情報の登録・更新
- 配送先住所の管理（複数登録可）
- 注文履歴の参照

### 4. 価格・割引計算
- 商品単価に基づく小計計算
- 割引ルールの適用（数量割引、クーポン割引、会員ランク割引）
- 税額計算
- 送料計算

### 5. 在庫引当
- 注文確定時の在庫引当
- 在庫不足時のエラーハンドリング
- キャンセル時の在庫戻し

## 成功の定義
- チームメンバーが各レイヤーの責務を説明できる
- ドメインロジックがドメイン層に集約されており、Application層やInfrastructure層に漏れ出していない
- 単体テストがドメイン層を中心に記述され、外部依存なしで実行できる
- 新しいビジネスルール追加時に、変更箇所が明確で影響範囲が限定的である

## ユーザーストーリー

### 注文作成
- **US-001**: 顧客として、カートに入れた商品を注文したい。注文時に在庫が確保され、合計金額が正しく計算されること。
- **US-002**: 顧客として、注文時に割引クーポンを適用したい。割引後の金額が正しく反映されること。
- **US-003**: 顧客として、複数の配送先住所から選択して注文したい。

### 注文ステータス管理
- **US-004**: 管理者として、注文のステータスを更新したい。不正なステータス遷移（例: 確定→配達完了）はシステムが拒否すること。
- **US-005**: 顧客として、注文の現在のステータスを確認したい。

### 注文キャンセル
- **US-006**: 顧客として、出荷前の注文をキャンセルしたい。キャンセル時に在庫が戻され、返金処理が開始されること。
- **US-007**: システムとして、出荷済みの注文のキャンセルを拒否したい。

### 商品・在庫管理
- **US-008**: 管理者として、商品を登録・更新したい。
- **US-009**: 管理者として、在庫数を確認・更新したい。在庫が閾値を下回った場合にアラートが発生すること。

### 価格計算
- **US-010**: システムとして、注文の合計金額を正しく計算したい。数量割引・クーポン割引・会員ランク割引を正しい優先順位で適用すること。

## 受け入れ条件

### 技術的な受け入れ条件
1. FastAPI + Python でバックエンドAPIを実装する
2. レイヤードアーキテクチャ（Presentation / Application / Domain / Infrastructure）に従う
3. ドメイン層は外部ライブラリ・フレームワークに依存しない
4. 集約ルート経由でのみドメインオブジェクトを操作する
5. リポジトリパターンでデータアクセスを抽象化する
6. ドメイン層の単体テストカバレッジ80%以上

### 機能的な受け入れ条件
1. 注文のステータス遷移が状態遷移図通りに制御される
2. 割引計算が仕様通りに動作する（優先順位: 会員ランク割引 → 数量割引 → クーポン割引）
3. 在庫引当と在庫戻しが正しく動作する
4. 不正な操作に対して適切なドメイン例外が発生する

## 機能要件

### ドメインモデル（集約）

#### 注文集約（Order Aggregate）
- 集約ルート: `Order`
- エンティティ: `OrderItem`（注文明細）
- 値オブジェクト: `OrderId`, `Money`, `Quantity`, `OrderStatus`
- ドメインイベント: `OrderPlaced`, `OrderCancelled`, `OrderShipped`

#### 商品集約（Product Aggregate）
- 集約ルート: `Product`
- 値オブジェクト: `ProductId`, `ProductName`, `Price`, `SKU`

#### 在庫集約（Stock Aggregate）
- 集約ルート: `Stock`
- 値オブジェクト: `StockQuantity`
- ドメインイベント: `StockAllocated`, `StockReleased`, `LowStockDetected`

#### 顧客集約（Customer Aggregate）
- 集約ルート: `Customer`
- エンティティ: `ShippingAddress`（配送先住所）
- 値オブジェクト: `CustomerId`, `CustomerName`, `Address`, `MemberRank`

### 注文ステータス遷移

```
[確定(CONFIRMED)]
    ↓
[支払済(PAID)]
    ↓
[出荷準備中(PREPARING)]
    ↓
[出荷済(SHIPPED)]
    ↓
[配達完了(DELIVERED)]

※ CONFIRMED, PAID, PREPARING の状態からのみキャンセル(CANCELLED)可能
※ SHIPPED, DELIVERED からのキャンセルは不可
```

### 割引ルール
1. **会員ランク割引**: ゴールド10%、シルバー5%、ブロンズ3%（小計に適用）
2. **数量割引**: 同一商品10個以上で5%OFF（商品単位に適用）
3. **クーポン割引**: 固定額割引または割合割引（最終合計に適用）

### API エンドポイント（主要なもの）
| メソッド | パス | 説明 |
|---------|------|------|
| POST | /api/orders | 注文作成 |
| GET | /api/orders/{id} | 注文詳細取得 |
| PUT | /api/orders/{id}/status | 注文ステータス更新 |
| POST | /api/orders/{id}/cancel | 注文キャンセル |
| GET | /api/products | 商品一覧取得 |
| POST | /api/products | 商品登録 |
| GET | /api/customers/{id} | 顧客情報取得 |
| GET | /api/customers/{id}/orders | 顧客注文履歴取得 |

## スコープ外
- 決済処理の実装（外部決済サービス連携はモック）
- フロントエンド実装（APIのみ）
- 認証・認可（簡易的なものに留める）
- メール通知（ドメインイベントの発行のみ、実際の送信はモック）
