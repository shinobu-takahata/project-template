# ISO/IEC 25010

## 1. 機能適合性 (Functional Suitability)

ユーザーの明示されたニーズ及び暗黙のニーズを満たす機能を提供しているか。

* **機能完全性 (Functional Completeness):** 必要な機能が全て揃っているか。（測定：不足している機能の割合）
* **機能正確性 (Functional Correctness):** 意図した結果を正しく提供できるか。（測定：計算ミスや処理誤りの発生率）
* **機能適切性 (Functional Appropriateness):** ユーザーの目的達成を助けるのに機能が「適切」か。（測定：目的達成のために必要な手順の過不足）

## 2. 性能効率性 (Performance Efficiency)

リソース量に対して、どれだけのパフォーマンスを発揮できるか。

* **時間効率性 (Time Behaviour):** 応答時間や処理時間が許容範囲か。（測定：平均応答時間、待ち時間、スループット）
* **資源効率性 (Resource Utilization):** CPU、メモリ、ディスクなどを無駄使いしていないか。（測定：ピーク時のメモリ使用量、CPU使用率）
* **容量 (Capacity):** 同時接続数やデータ量の上限は十分か。（測定：最大同時ユーザー数、最大データ通信量）

## 3. 互換性 (Compatibility)

他の製品や環境と情報を共有したり、同じ環境で共存したりできるか。

* **共存性 (Co-existence):** 同じ環境にある他のソフトに悪影響を与えないか。（測定：他ソフト併用時の障害発生数）
* **相互運用性 (Interoperability):** 他のシステムとデータをやり取りし、活用できるか。（測定：データ交換フォーマットの適合率）

## 4. 使用性 (Usability)

ユーザーが製品を理解し、学び、使い、魅力的に感じる度合い。

* **適切性認識性 (Appropriateness Recognizability):** 自分のニーズに合うソフトだと一目でわかるか。（測定：デモ後のユーザーの理解度）
* **習得性 (Learnability):** 使い方をすぐに覚えられるか。（測定：操作習得までにかかる時間）
* **運用操作性 (Operability):** 簡単に操作できるか。（測定：カスタマイズのしやすさ、操作の取り消し可能性）
* **ユーザーエラー防御性 (User Error Protection):** ユーザーがミスをしないよう守られているか。（測定：誤操作の回避率、エラーメッセージの分かりやすさ）
* **ユーザーインタフェース快感性 (User Interface Aesthetics):** 見た目が心地よいか。（測定：視認性やデザインの満足度）
* **アクセシビリティ (Accessibility):** 障がい者や高齢者を含む多様な人が使えるか。（測定：ガイドラインへの適合項目数）

## 5. 信頼性 (Reliability)

特定の条件下、特定の期間において、システムが意図した機能を実行できる度合い。

* **成熟性 (Maturity):** 普通に使っていて故障しないか。（測定：故障間隔、バグ密度）
* **可用性 (Availability):** 必要な時にいつでも使える状態か。（測定：アップタイム、稼働率）
* **障害許容性 (Fault Tolerance):** 故障しても機能を維持できるか。（測定：一部故障時の機能維持率）
* **回復性 (Recoverability):** 故障したあと、データを復旧し再開できるか。（測定：復旧までの平均時間）

## 6. セキュリティ (Security)

情報やデータを保護し、権限に応じたアクセスを維持する度合い。

* **機密性 (Confidentiality):** 権限のない人に情報が漏れないか。（測定：データ暗号化の適用率）
* **完全性 (Integrity):** データが不正に書き換えられないか。（測定：不当なデータ改ざんの検出数）
* **否認防止性 (Non-repudiation):** 「やっていない」という嘘を防止できるか。（測定：操作ログの網羅率）
* **責任追跡性 (Accountability):** 誰が何をしたか追跡できるか。（測定：ユーザー識別とログの紐付け精度）
* **真正性 (Authenticity):** 本人であることを証明できるか。（測定：認証の強固さ、なりすまし成功率の低さ）

## 7. 保守性 (Maintainability)

修正、改良、または環境の変化に適応させる際の効率の良さ。

* **モジュール性 (Modularity):** 各部品が独立しているか。（測定：変更時の他箇所への影響度）
* **再利用性 (Reusability):** 他のプログラムで再利用できるか。（測定：共通化されている資産の割合）
* **解析性 (Analyzability):** 故障の原因や変更箇所をすぐ特定できるか。（測定：ログの充実度、コードの可読性）
* **修正性 (Modifiability):** バグ修正や機能変更を素早く行えるか。（測定：修正に伴う工数、複雑度）
* **試験性 (Testability):** テストをしやすいか。（測定：自動テスト網羅率、テストケースの作成容易性）

## 8. 移植性 (Portability)

一つの環境から別の環境へ移す際の効率の良さ。

* **適応性 (Adaptability):** 異なる環境にスムーズに適応できるか。（測定：OS変更時の修正箇所数）
* **設置性 (Installability):** インストールが簡単にできるか。（測定：インストールにかかる時間、成功率）
* **置換性 (Replaceability):** 別のソフトから簡単に乗り換えられるか。（測定：旧データからのインポート成功率）

---

> **測定のポイント**
> 各特性は、**「内部測定（ソースコード等）」「外部測定（動作中）」「利用時の品質（ユーザー実感）」**の3段階で計測されます。JIS X 25023は主に「外部」と「内部」の客観的な数値を網羅しています。





# ISO/IEC25023
利用時の内部品質と外部品質について言及

1. 機能適合性 (Functional Suitability)

```csv
ID,名称,計算式（計測機能）,解説
FCp1G,機能網羅性,X=1−(A/B),A:不足機能数 / B:要求機能数。1に近いほど仕様を満たす。
FCr1G,機能正確性,X=1−(A/B),A:不正確な結果数 / B:実施したテスト数。精度の高さを測る。
FAp1G,機能適切性,X=A/B,A:目的達成に適切な機能数 / B:評価対象の全機能数。
```


2. 性能効率性 (Performance Efficiency)

```csv
ID,名称,計算式（計測機能）,解説
PTb1G,平均応答時間,X=∑Ti​/n,T:応答時間 / n:処理件数。ユーザーの待ち時間の平均。
PTb5G,平均スループット,X=n/T,n:完了件数 / T:測定時間。単位時間あたりの処理能力。
PRu2G,平均メモリ使用率,X=∑Mi​/n,M:各時点のメモリ使用量。リソースの節約度を測る。
```


5. 信頼性 (Reliability)
```
ID,名称,計算式（計測機能）,解説
RMa1G,故障密度,X=A/B,A:検出された故障数 / B:ソースコード行数(KLOC)など。
RAv1G,可用性,X=Tup​/(Tup​+Tdown​),稼働時間 ÷ (稼働時間 + 停止時間)。システムの稼働率。
RRe1G,平均復旧時間,X=∑Ti​/n,故障発生から復旧までにかかった時間の平均。
```


6. セキュリティ (Security)
```
ID,名称,計算式（計測機能）,解説
SCf1G,データ暗号化比率,X=A/B,A:暗号化されているデータ項目数 / B:保護が必要な全項目数。
SAc1G,アクセス制御の適合性,X=A/B,A:正しく制御されたアクセス数 / B:テストした全試行数。
SAn1G,ログの完全性,X=A/B,A:ログに残っている重要操作数 / B:実際に実行された重要操作数。
```


7. 保守性 (Maintainability)
```
ID,名称,計算式（計測機能）,解説
MAn1G,診断機能の網羅性,X=A/B,A:自動診断で検知できる故障数 / B:想定される全故障数。
MMo1G,修正時間効率性,X=A/B,A:実際の修正時間 / B:予測された修正時間。
MTs1G,テスト自働化率,X=A/B,A:自動化されたテストケース数 / B:全テストケース数。
```
